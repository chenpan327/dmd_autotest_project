### 3.1 架构

```

        ▼
台架节点 10.10.4.176  ←── 真机串口/UDP 都接在这台
```

- Agent 已注册为 Windows 服务（服务名 `JenkinsAgent-10.10.4.176`，开机自启），`tools/java-agent/` 下有 `agent.jar`、`jenkins-agent-service.xml`、日志目录。**换节点/重装**时：改 xml 里的 secret 与路径 → `jenkins-agent-service.xml` 重新注册服务即可。

### 3.2 Job 参数

| 参数 | 取值 | 说明 |
|------|------|------|
| `DeviceType` | 各机型（V4/L3/X1/…）或 `BSP_APP` | 选 `BSP_APP` 时必须再选 `BoardType` |
| `BoardType` | RDKS100 / hope_stm32h743vit6 / host / hrw_stm32u073cbt6_eval / mobai_gd32l233kbg6_core / qsyx_stm32f030cct6_core / weact_stm32g431cbu6 | 板名 = config.json 顶层键 |

实际分发为 `main.py --device_type <设备或板名> --test_suites <套件>`（BSP_APP 时 BoardType 替换 DeviceType）。构建脚本 `jenkins_build_script.bat` 自动建 `.venv`、装依赖、清空 allure-results。

### 3.3 构建脚本维护注意（jenkins_build_script.bat 头部注释已写明）

1. 保存为 UTF-8 **无 BOM**；`chcp 65001` 保证中文显示。
2. `echo` 行里的 `|` `<` `>` `&` `^` 必须转义——曾因裸管道符导致构建 "not recognized" 失败。
3. REM 注释行**只许 ASCII**：混入中文注释会被 cmd 在 65001 代码页下误解析成命令随机执行。
4. `PROJECT_ROOT` 默认 `D:\workspace\code\dmd_autotest_project`——这是**台架真实路径，不是 bug**（开发机在 C:\，是两台不同的机器）。

## 4. 固件 CI/CD 全链路（对应《GitLab-CICD全链路培训.html》）

> 该培训文档是这一节的标准答案，本节只摘交接必知。文档位置：`C:\workspace\file\GitLab-CICD全链路培训.html`（建议随本仓库 docs/ 一起归档）。

### 4.1 链路一句话

唯一人工入口是**打附注 tag**；之后 GitLab 流水线（cppcheck → build → release → notify 四个 stage）自动完成：west 全量编译 → 生成 MD5 → 上传 Nexus → 飞书工作项自动评论/回填交付物/节点流转 →（可选）测试群卡片通知。日常 push 与 MR 只跑 cppcheck + 编译验证，不上传不通知。

### 4.2 发版两条命令（全部要背的就这些）

```bash
git tag -a test_0.1.1 -m "test_0.1.1 发布 需求:m-xxx 缺陷:f-xxx"   # 注释里写工作项 ID
git push origin test_0.1.1                                        # 之后全自动，约十几分钟
```

- tag 前缀即用途：`debug_`（研发自测）/ `test_`（发测试组）/ `dmd_`（发生产/技术支持）。
- 回链失败**不用重新打 tag**：Pipelines 页对 `feishu_notify` job 点 Retry 即可。
- 删错 tag 重打：`git tag -d <tag> && git push origin :refs/tags/<tag>`。

### 4.3 GitLab Variables（Settings → CI/CD → Variables）

| 类别 | 变量 | 存放位置 | 缺失后果 |
|------|------|---------|---------|
| 密钥类（Masked） | `FEISHU_PLUGIN_ID` / `FEISHU_PLUGIN_SECRET` / `FEISHU_USER_KEY` / `FEISHU_PROJECT_KEY`（tgrjrf）/ `FEISHU_BOT_WEBHOOK_URL`（可选）/ `GITLAB_API_TOKEN`（可选） | GitLab 设置页 | 回链整体无法鉴权；webhook 缺失仅群通知跳过 |
| yml variables 区 | `FEISHU_WORK_ITEM_TYPES`（前缀→真实 type_key 映射）、`FEISHU_WORK_ITEM_FLOW`（哪些前缀发版后自动 confirm 节点）、`FEISHU_DELIVERABLE_FIELDS`（交付物字段 key）、`FEISHU_DRY_RUN`（true=只打印不真发，调试开关）、`NEXUS_URL` / `NEXUS_REPO` | 仓库 `.gitlab-ci.yml` | 改这些 = 改 yml 提交 |

**交接要点**：密钥类变量是 Masked 的，GitLab 里配好后无法再查看原文。接手后第一件事与移交人当面过一遍这些变量（或重建），否则下一次发版的飞书回链会静默降级（job 绿但没通知）。

### 4.4 排障速查（详细表见培训文档 §3.6）

| 现象 / 错误码 | 含义 | 处理 |
|--------------|------|------|
| 发版后工作项没收到评论/回填 | tag 注释和 commit message 都没写工作项 ID（非强制特性，流水线绿但跳过回链） | 手动跑流水线传 `FEISHU_WORKITEM_IDS=m-xxx` 后 Retry notify |
| 50006 / 30005 / 20003 | 工作项 ID 与真实 type_key 不匹配（URL 里的是前端别名，API 不认） | `GET /open_api/{key}/work_item/all-types` 查真实 key，更新 `FEISHU_WORK_ITEM_TYPES` |
| 10301 | 插件缺权限 scope | openapp → 插件 → 权限管理申请 → 发布新版本 → 空间里更新 |
| 10021（流转/回填段） | 代码漏带 `X-PLUGIN-TOKEN`/`X-USER-KEY` 鉴权头（401 会被降级设计吞掉，job 依然绿） | 对照评论调用的写法补头；从「流转汇总」日志发现 |
| 10429 | 飞书限流（单接口 15 QPS） | 正常重试即可 |
| Nexus 直链 404 | 未登录 Nexus 的会话无下载权限 | 浏览器登录后再访问，或用交付物里的 browse 链接 |
| 流转汇总「无进行中节点」 | 该工作项流程已走完 | 正常降级，无需处理 |

### 5.4 地面站 DGCS / 云平台 / 压测

- 压测（模拟飞机）：单机 scapy 串行发送有物理上限，1000 架必然抖动（物理层瓶颈非判定逻辑），减数量或多机分布式是根本方案；集群版 master/slave（TCP 19999）+ 单机 P0/P1 优化后单机上限约 3000。
- GCS 飞机身份：UavManager 按 MAC/IP 路由（不是 sys_id），Online 判定 = WORKING + 6s 超时回退——压测工具必须同步带超时清零才会跟着地面站抖动。
